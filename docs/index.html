01Overview

        
Each SDK wraps the same Yativo Fiat API: every endpoint, the same method names, and the same behaviour. Pick your language once above, and every example on this page follows it. Each card opens the SDK's repository, with a step-by-step README, runnable examples and test results.

        

          
JS
Node.js / TypeScript
Typed client for Node 18+, with Express, Next.js and plain http webhook handlers.
@yativo/fiat-sdk

          
Py
Python
Standard library only. Python 3.8+, with Flask, Django and FastAPI webhook views.
yativo-fiat-sdk

          
PHP
PHP
PHP 8.1+, needs only the curl and json extensions. Works in any framework.
yativo/fiat-sdk

          
L
Laravel
Config, a facade, a signed webhook route and Laravel events. Laravel 10 to 13.
yativo/fiat-sdk-laravel

          
Go
Go
Standard library only. Go 1.18+, with an http.Handler for webhooks.
github.com/Yativo/yativo-fiat-go

          
WP
WooCommerce plugin
Local payment methods and cards at checkout. Classic and block checkout.
yativo-payments

        


        
What every SDK does for you

        

          
Authentication
Sends X-Api-Key and X-Api-Secret on every request. No login call, no tokens to refresh.

          
Safe retries
Retries network errors, 429 and 5xx with backoff, reusing the same Idempotency-Key so nothing runs twice.

          
Webhook verification
Checks the Signature header in constant time and routes events to your handlers.

          
Secrets stay secret
Credentials never appear in logs, error messages or debug output. HTTPS is required.

        

      


      
      

        
02Before you start

        
You need an API key, and the IP address of every server that will call Yativo.

        

          
          
1
Create an API key
Sign in to app.yativo.com and go to Developers → API Keys. API access is available once your business KYC is approved.

          
2
Add your server IPs
Add the IP address of each server that uses the key. Requests from any other address are refused.

          
3
Store the secret safely
The API secret is shown once. Put it in a secrets manager or environment variable, never in code or a browser.

          
4
Start in sandbox
Sandbox has its own keys and moves no real money. Switch to production when you're ready.

        

        

          

            
EnvironmentBase URLSDK setting

            
              
Productionhttps://api.yativo.com/api/v1production (default)

              
Sandboxhttps://smtp.yativo.com/api/v1sandbox

            
          

        

        

          
          
Use the SDKs on your server only. The browser and mobile apps must never hold your API secret. The Node.js SDK refuses to start in a browser.

05Making requests

        
Every endpoint is a method on a resource: deposits.create, payouts.list, virtualAccounts.retrieve. Path parameters come first, then the body or the query filters.

        

          
          
          
          
          
        

        
Methods return the response's data. Lists return the items with their pagination. Field names are exactly what the API returns. See the API docs for each endpoint's fields.


        
Idempotency

        
Every POST, PUT, PATCH and DELETE carries an Idempotency-Key. The SDK generates one for you. Pass your own, such as your order ID, so a retry after a crash can't pay or collect twice.

        

          
          
          
          
          
        

        

          
          
Yativo keeps the first response for a key for 60 minutes. Reusing a key with a different body returns 409. Use a new key for each new operation.

        


        
Retries and timeouts

        
Network errors, 429, 500, 502, 503 and 504 are retried twice by default, with exponential backoff and the Retry-After header. Each retry uses the same idempotency key. Other errors are never retried.

        

          
          
          
          
          
        


        
Endpoints the SDK doesn't wrap yet

        
Call any path with the same authentication, retries and error handling. You get the full response envelope.

08Collect payments

        
A deposit (payin) gives your payer a hosted page for a local payment method: a bank transfer, PIX, SPEI, SEPA, a card and more.

        

          
          
1
Find a payment method
List payin methods for a country (three-letter code) and currency. The method's id is the gateway for the deposit.

          
2
Create the deposit
amount is in the method's currency. currency is the wallet you're credited in: one of the method's base_currency values.

          
3
Send the payer to deposit_url
They pay on Yativo's page and come back to your redirect_url (cards use return_url).

          
4
Confirm, then fulfil
On a deposit.updated webhook, read the deposit from the API and fulfil when its status is success.

        

        

          
          
          
          
          
        


        
Confirm a deposit

        
A redirect back to your site isn't proof of payment: browsers close, and URLs can be typed by hand. Read the deposit from the API before you fulfil.

        

          
          
          
          
          
        

        
Deposit status is pending, processing, success, failed, cancelled or expired.


        
Lock the exchange rate

        
To show the payer an exact amount, create a quote first. It locks the rate for 5 minutes. Pass its quote_id instead of amount.

        

          
          
          
          
          
        

      


      
      

        
09Card Checkout

        
Hosted card payments, including Apple Pay and Google Pay, for your customers' sales. Card details are entered on Yativo's page and never reach your servers.

        

          
          
Your account needs Card Checkout access (cardCheckout.requestAccess), and the selling customer needs an approved card_checkout endorsement (cardCheckout.submitEndorsement). Only USD is enabled today.

        

        

          
          
          
          
          
        

        
Only the card_checkout.order.paid webhook, confirmed with cardCheckout.retrieveOrder, means the buyer paid. The link expires after 60 minutes. Test cards in sandbox: 4242 4242 4242 4242 succeeds, 4000 0000 0000 0002 is declined.

      


      
      

        
10Send payouts

        
Save the recipient as a beneficiary, quote the payout, then send it from a wallet.

        

          
          
          
          
          
        

        
Payouts report their progress through the payout.updated webhook: pending, processing, completed, failed, cancelled or refunded.

      


      
      

        
11Webhooks

        
Yativo sends a signed POST to your URL when something changes. Every SDK verifies the signature and routes events to your handlers.

        

          

            
              
Signature headerSignature: hex(HMAC-SHA256(raw body, webhook secret))

              
Body{ "event.type": "deposit.updated", "payload": { ... } }

              
TimeoutAnswer within 3 seconds with any 2xx

              
RetriesUp to 3 attempts in total, then you can resend from the delivery log

            
          

        


        
Register your URL

        
Your account has one webhook URL. Registering returns the secret you verify with. Store it as YATIVO_WEBHOOK_SECRET.

        

          
          
          
          
          
        


        
Handle events

        
Verify the raw body. Parsing the JSON first changes the bytes and breaks the signature. Then confirm the payment with the API before you act: the event tells you what changed, the API tells you the truth.

        

          
          
          
          
          
        


        
Verify by hand

        
Already have a route? Verify and decode a single delivery.

        

          
          
          
          
          
        


        
Event types

        

          

            
EventSent when

            
              
deposit.created, deposit.updatedA deposit is created, or its status changes

              
card_checkout.order.*A card order changes: paid, payment_failed, refunded, disputed, expired and more

              
payout.updatedA payout changes status

              
virtual_account.depositMoney lands in a virtual account

              
customer.created, customer.updatedA customer is created or changes

              
endorsement.updatedA customer's KYC or KYB result changes

              
crypto.deposit.completedA stablecoin deposit lands

              
virtualcard.*, business_spend_card.*Card lifecycle, funding and transactions

              
webhook_updatedOnce, right after you register your URL

            
          

        

        
New event types are added over time, so ignore ones you don't handle. The same event can arrive more than once and out of order: store event.key (Node: eventKey(event), Go: event.Key(), PHP: $event->key()) and skip ones you've processed.


        
Test in sandbox

        

          
          
          
          
          
        

        
Other sample types include payout, virtual_account, customer, endorsement and webhook_updated. Sample events are signed like real ones.

      


      
      

        
12Laravel

        
The Laravel package registers the client, a facade, a signed webhook route and Laravel events. It's discovered automatically.

        

          
          
        

        
    
          
  • Webhook route: POST /webhooks/yativo in the api middleware group, with the signature checked by the yativo.signature middleware. Turn it off with YATIVO_WEBHOOK_ROUTE=false and add Route::yativoWebhooks('your/path') yourself.
    • 
          
  • Events: every verified delivery fires Yativo\Fiat\Laravel\Events\WebhookReceived and yativo.{event type}, such as yativo.deposit.updated.
    • 
          
  • Queues: listeners that implement ShouldQueue run on your queue, which keeps the response inside the 3-second limit.
    • 
          
  • Duplicates: deliveries already handled are skipped using your cache. A delivery is only remembered after your listeners succeed, so a failure is retried.
    • 
        

        

          
        

      


      
      

        
13WordPress & WooCommerce

        
The Yativo Payments plugin adds local payment methods and cards to your WooCommerce checkout. Orders are marked paid only after the plugin reads the payment from the Yativo API.

        

          
Local payments
Bank transfers and local methods for your country and store currency. The customer pays on Yativo's page.

          
Cards
Cards, Apple Pay and Google Pay through Card Checkout, for USD stores. Card details never touch your site.

        

        

          
          
1
Install
Download yativo-payments.zip from the latest release, then go to Plugins → Add New → Upload Plugin and activate it. WooCommerce must be active.

          
2
Add your API key
Go to WooCommerce → Settings → Yativo. Choose the environment, enter the API key and secret, and click Test connection.

          
3
Register the webhook URL
Click Register webhook URL. The plugin saves the webhook secret for you. This replaces any webhook URL already set on your Yativo account.

          
4
Turn on the payment methods
In WooCommerce → Settings → Payments, open Yativo local payments, enter your country, click Load payment methods and pick them. For Yativo cards, enter the seller customer ID.

        

        
Keep secrets out of the database

        
Define the credentials in wp-config.php instead of saving them in the settings. Constants take priority.

        

          
        

        

          

            
Yativo statusWooCommerce order

            
              
Deposit success or card paid, amount matchesProcessing (paid)

              
Paid amount doesn't match the orderOn hold, with a note

              
Card payment under review or disputedOn hold

              
Deposit failed, cancelled or expired; card link expiredFailed. The customer can pay again

              
Card payment refundedRefunded

            
          

        

        
    
          
  • Works with the classic checkout and the block checkout, and with WooCommerce order storage (HPOS).
    • 
          
  • The webhook endpoint is https://your-site/wp-json/yativo/v1/webhook. Every request is checked against the webhook secret.
    • 
          
  • Saved secrets are never shown again in the settings page, and the optional debug log never contains them.
    • 
          
  • Refunds are made in Yativo. Card refunds made there are reflected on the order.
    •

15Security checklist

        
What the SDKs handle, and what's on you.

        

          
Handled by the SDKs

            
    
              
  • HTTPS only. Redirects are never followed, so your key can't be sent elsewhere.
    • 
              
  • Credentials are kept out of logs, print/var_dump output, errors and serialization.
    • 
              
  • Webhook signatures are compared in constant time.
    • 
              
  • Path parameters are URL-encoded, and auth headers can't be overridden.
    • 
              
  • No third-party runtime dependencies.
    • 
            

          

          
Your part

            
    
              
  • Keep keys in a secrets manager or environment variables. Never commit them.
    • 
              
  • Call Yativo from your servers only, never from browsers or apps.
    • 
              
  • Use one API key per system, with only that system's IPs.
    • 
              
  • Confirm payments with the API before you fulfil.
    • 
              
  • Rotate the webhook secret with webhookEndpoints.regenerateSecret if it may have leaked.
    •
